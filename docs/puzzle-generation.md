# Daily Puzzle Generation

Each day, GlowGrid generates a unique puzzle state using a deterministic process seeded by the date. The same date always produces the same puzzle, regardless of device or timezone.

## Overview

1. Derive a **numeric seed** from the date
2. Initialize a **seeded PRNG** (pseudo-random number generator)
3. Start from an **all-ON** grid (the goal state)
4. Apply **10 random reverse-moves** to scramble the grid
5. The resulting state is the puzzle — it is **guaranteed solvable** because it was constructed by working backwards from the solution

---

## Step 1: Date Seed

The date key format is `YYYY-M-D` (no zero-padding). The seed is computed as:

```
seed = year × 10000 + month × 100 + day
```

**Examples:**

| Date           | Key        | Seed      |
|----------------|------------|-----------|
| Jan 1, 2025    | `2025-1-1` | 20250101  |
| May 11, 2026   | `2026-5-11`| 20260511  |
| Dec 25, 2025   | `2025-12-25`| 20251225 |

## Step 2: Seeded PRNG — Mulberry32

The game uses [Mulberry32](https://gist.github.com/tommyettinger/46a874533244883189143505d203312c), a fast 32-bit PRNG that produces deterministic sequences from a given seed.

```javascript
function mulberry32(seed) {
  return () => {
    seed |= 0;
    seed = seed + 0x6D2B79F5 | 0;
    let t = Math.imul(seed ^ seed >>> 15, 1 | seed);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}
```

Each call returns a float in `[0, 1)`. The sequence is fully determined by the initial seed.

## Step 3: Start from the Goal

The grid starts in the **all-ON** state (all 25 cells lit):

```
■ ■ ■ ■ ■
■ ■ ■ ■ ■
■ ■ ■ ■ ■
■ ■ ■ ■ ■
■ ■ ■ ■ ■
```

This is the win condition — the target the player must reach.

## Step 4: Scramble with 10 Random Moves

The generator applies **10 random toggle moves** to the solved grid:

```javascript
function generatePuzzleForKey(key) {
  const rng = mulberry32(seedFromKey(key));
  state = Array(SIZE * SIZE).fill(true);  // all ON
  for (let k = 0; k < 10; k++) {
    applyToggle(Math.floor(rng() * SIZE * SIZE));
  }
  puzzleState = state.slice();
}
```

Each move picks a random cell (0–24) and applies `applyToggle()` — the same toggle logic the player uses. This means the resulting puzzle is always solvable: replaying those 10 moves in reverse order would restore the all-ON state.

> **Note:** The actual optimal solution may be shorter than 10 moves, because some random moves may cancel each other out or create more efficient paths. A bidirectional BFS solver finds the shortest solution for hints.

---

## Toggle Mechanics

Toggling a cell flips it **and** its neighbors. The pattern depends on the cell's current state:

### ON cell → Plus (+) pattern

Flips the cell itself and its orthogonal neighbors (up, down, left, right):

```
    ■
  ■ ● ■
    ■
```

### OFF cell → Cross (×) pattern

Flips the cell itself and its diagonal neighbors:

```
  ■   ■
    ●
  ■   ■
```

### Edge behavior

Neighbors that would fall outside the grid are simply ignored. A corner cell's plus pattern affects only 3 cells; an edge cell affects 4; a center cell affects 5.

**Examples for a 5×5 grid:**

| Cell | Position    | Plus pattern        | Cross pattern       |
|------|-------------|---------------------|---------------------|
| 0    | Top-left    | 0, 1, 5             | 0, 6                |
| 2    | Top-center  | 2, 1, 3, 7          | 2, 6, 8             |
| 12   | Center      | 12, 7, 11, 13, 17   | 12, 6, 8, 16, 18    |
| 24   | Bottom-right| 24, 19, 23           | 24, 18              |

---

## Why Solvability Is Guaranteed

The puzzle is generated by starting from the solved state and applying legal game moves backwards. Since every move is its own inverse (toggling twice returns to the original state), the puzzle can always be solved by replaying the same 10 random moves.

In practice, the optimal solution is typically shorter. The game's built-in solver uses **bidirectional BFS** to find the minimum number of moves.

---

## Determinism Across Devices

The generation is fully deterministic because:

1. **Date-based seed** — same date → same seed everywhere
2. **Mulberry32 PRNG** — pure integer arithmetic, no floating-point platform variance
3. **Fixed algorithm** — always 10 moves from the same starting state
4. **No timezone dependency in seed** — uses local date components directly

Two players on different devices opening the same day's puzzle will always see the identical grid.
